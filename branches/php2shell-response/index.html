Technik verständlich

Was liegt „dazwischen“?

Bei CVE-2026-109619 geht es um den Speicher eines wiederverwendeten PHP-Workers. Eine frühere Anfrage kann internen Zustand zurücklassen, dessen Speicher schon freigegeben wurde. Eine spätere Anfrage kann diesen Zustand vor dem normalen Zurücksetzen berühren.

REQUEST A

Ein Zustand wird gesetzt

Die erste Anfrage nutzt PHP-interne Daten. Ein Fehler kann den vorgesehenen Reset unterbrechen.

WORKER

Speicher wird freigegeben

Der Worker lebt weiter, während ein Verweis auf anfragegebundenen Speicher zurückbleibt.

REQUEST B

Alter Verweis wird benutzt

Vor der normalen Initialisierung greift PHP unter bestimmten Bedingungen auf den veralteten Zustand zu.

Begriffsklärung: Das ist ein Request-übergreifender Speicherfehler im PHP-Kern. Die bisher belegte Fehlerkette ist kein klassischer Man-in-the-Middle im Netzwerk und kein allgemein belegter Authentifizierungs-Bypass. Original-Advisory lesen.

Die sechs Prüfhandlungen

Ein nachvollziehbarer Fix besteht aus mehreren beobachteten Zuständen. Eine installierte Datei ist noch kein Beleg, dass der Web-Worker diese Datei ausführt.

  1. Aktive Runtime inventarisierenPro Webanwendung PHP-Version, SAPI, Paket- oder Image-Quelle, Erreichbarkeit und Verantwortliche erfassen. Die CLI-Version kann von der Web-Runtime abweichen.
  2. Passenden Patch anwendenPHP 8.2.35, 8.3.36, 8.4.27, 8.5.12 oder den konkret belegten Vendor-Backport einsetzen. Alte Zweige benötigen eine eigene Migrationsentscheidung.
  3. Alle betroffenen Worker neu startenDamit nicht weiter ein alter Prozess läuft. Der Neustart und sein Zeitpunkt gehören zum Nachweis.
  4. Den laufenden Build prüfenÜber einen internen Administrationsweg SAPI, Paketbuild und aktiven Worker nach dem Neustart beobachten. Keine öffentliche Diagnose-Seite hinterlassen.
  5. Normale Funktionen testenLogin, Sessions, Uploads, Formulare und zentrale Fehlerpfade mit harmlosen Tests prüfen. Das zeigt Funktion, nicht die Abwesenheit früherer Angriffe.
  6. Altaktivität getrennt untersuchenErhaltene eigene Telemetrie seit mindestens 17. Oktober auswerten. Exploit-Versuch, erfolgreiche Wirkung und Datenabfluss sind verschiedene Befunde.
Neuer Hinweis vom 23. Oktober: PHP nennt mit CVE-2026-115560 einen zusätzlichen, ungewöhnlichen Session-Upload-Progress-Pfad und empfiehlt bei der genannten Konfiguration vorübergehend session.upload_progress.enabled=0. Aktuelle PHP-Meldung.
